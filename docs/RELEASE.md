# Как выпускать релизы

Коротко: **никаких ключей заводить не нужно.** Для сборки и выкладывания
файла GitHub выдаёт токен сам. Настроить надо одну галочку и один раз.

## Что включить в настройках репозитория

**Settings → Actions → General → Workflow permissions**

Выберите **Read and write permissions** и сохраните. Без этого сборка
отработает, но приложить файл к релизу не сможет: у неё будет право только
читать.

Это всё. Секрет для этого не нужен: `GITHUB_TOKEN` выдаётся каждому запуску
автоматически, живёт только пока идёт сборка и действует только в пределах
этого репозитория. Свой ключ здесь был бы лишним риском — он живёт дольше
и обычно может больше.

## Как выпустить

Версия живёт в одном месте — `src/version.zig`. Метка обязана ей
соответствовать, и сборка это проверяет: если разойдутся, релиз не выйдет.

```
git tag v0.1.20.0
git push origin v0.1.20.0
```

Дальше само: прогоняются тесты, собирается релизный exe, сверяется версия,
файл прикладывается к релизу, описание собирается из коммитов.

## Когда ключ всё-таки нужен

Свой ключ нужен только там, где GitHub не может выдать свой:

| Зачем | Что заводить | Где |
|---|---|---|
| Подписать exe, чтобы SmartScreen не ругался на скачанный файл | сертификат подписи кода и пароль к нему | Settings → Secrets and variables → Actions → New repository secret |
| Выложить не только на GitHub (свой сайт, хранилище) | ключ доступа того сервиса | там же |
| Отправлять из сборки в чужой репозиторий | токен с правом записи в тот репозиторий | там же |

Правила для любого такого секрета:

* заводить **тонко настроенный** токен (fine-grained), а не классический:
  классический даёт доступ ко всем вашим репозиториям сразу;
* выбирать только этот репозиторий и только нужное право;
* ставить срок жизни, а не «бессрочно»;
* хранить только в Secrets. В переменные окружения машины, в файлы репозитория
  и в текст задач токены не кладут: оттуда они утекают тихо и незаметно.

Секрет виден сборке как `${{ secrets.ИМЯ }}` и никогда не показывается
в журнале — GitHub затирает его в выводе.

## Про подпись exe

Пока файл не подписан, Windows при скачивании покажет предупреждение
SmartScreen. Это не ошибка сборки и не признак вируса — так ведёт себя любой
неподписанный exe от небольшого издателя. Подпись стоит денег и требует
проверки личности; до тех пор честнее написать об этом в README, чем делать
вид, что предупреждения не будет.
